# 首次启动与登录前偏好引导

> 状态：进行中
> 记录日期：2026-09-20

## 一、要解决的问题

当前首次体验被拆成了两个弹窗：

- 未登录时，在登录页上覆盖“选择界面语言”弹窗；
- 登录成功并进入主界面后，再覆盖“学习语言 + 学习难度”弹窗。

这套体验视觉上像临时配置，也让用户在已经进入产品后再次被打断。新的首次体验应当是一段完整的登录前引导：用户先完成使用 OIO 所必需的基础选择，再进入登录或注册；登录成功后把本次选择同步到账户，不再弹出重复的学习偏好窗口。

## 二、目标流程

```text
首次安装启动
  → 1/4 选择 App 语言
  → 2/4 选择要学习的语言
  → 3/4 选择学习难度
  → 4/4 选择从哪里知道 OIO
  → 登录 / 注册
  → 登录成功后同步到 OIO 账户
  → 进入主界面，不再弹学习偏好窗口
```

四步都必须完成，不提供“跳过”。第二至第四步允许返回修改；每一步没有选择时，“继续”按钮不可用。它应当是独立的全屏引导页面，而不是在登录页或主界面上继续叠 `Modal`。

## 三、四步内容

### 1. App 语言

沿用当前支持的四种界面语言：

- 简体中文
- 繁體中文
- English
- 日本語

语言名称始终使用自身语言显示，避免用户尚未选择界面语言时无法阅读。选择后界面立即切换，后续三步和登录页都使用该语言；返回本页重新选择时也即时切换。

### 2. 学习语言

沿用当前 OIO 实际支持的学习语言选项。第一版保持与“我 > 语言设置”一致，不在引导页创造一套独立枚举。

### 3. 学习难度

沿用当前的难度选项及服务端含义。选项文案需要解释它将影响改写、回复和练习内容，不能只显示内部等级名。

### 4. 从哪里知道 OIO

单选且必选，第一版固定为：

- YouTube
- 小红书
- 抖音
- App Store
- Google Play

第一版不擅自增加“其他”或“朋友推荐”。渠道是产品归因信息，不应混入可随时修改的学习偏好，也不应写入 Authing 自定义字段。

## 四、首次用户的判定

这里的“第一次”定义为**当前安装第一次启动**，不是“这个账号一生只展示一次”。原因是引导发生在登录之前，此时 App 还不知道用户将登录哪个账号。

判定规则：

1. 全新安装、没有本地使用证据：展示四步引导；
2. 同一安装已经完成引导，后来退出登录：直接进入登录页，不重复展示；
3. 已登录用户升级 App：不展示；
4. 旧版本升级且本地已有语言、Session、Guide State 或其他历史数据：视为已有安装，不强制补做；
5. 卸载重装、清空 App 数据或更换设备：会再次展示，这是登录前流程无法识别账户身份时的预期行为。

现有 `reconcileLocalInstallState()` 已能依据安装标记和本地数据判断全新安装，可作为入口判断，但不能只检查新的“引导完成”Key，否则升级后的所有老用户都会被误伤。

## 五、本地保存与登录后同步

未登录阶段建立一个带版本的本地草稿，例如：

```ts
type PreLoginOnboardingDraftV1 = {
  appLocale: AppLocale;
  learningLanguage: LearningLanguage;
  promptDifficulty: PromptDifficulty;
  acquisitionSource: "youtube" | "xiaohongshu" | "douyin" | "app_store" | "google_play";
  completedAt: string;
};
```

保存规则：

- 每一步选择即时保存草稿，App 中断后可以回到未完成的步骤；
- 只有四步都完成后才写“登录前引导完成”标记并进入登录页；
- App 语言继续写入现有 i18n 本地 Key，保证登录页立即使用所选语言；
- 登录成功后用一个幂等同步操作写入账户，再清除待同步状态；
- 网络失败不能阻止用户进入 App，保留 `pendingSync` 并在本次启动或下次启动重试；
- 同步成功后，服务端返回值重新落回本地，避免本地与云端长期分叉。

### 登录后的覆盖规则

用户刚刚在本次引导中主动完成的 App 语言、学习语言和难度，视为最新明确选择，登录后更新到该账户。若没有本次待同步草稿（普通登录、恢复 Session），则以服务端账户偏好为准并回写本地。

来源渠道建议采用“首次有效值”规则：账户尚无来源时写入；账户已有来源时不被重装或换设备覆盖。这样既满足新用户归因，也不会让老账号重复安装后污染来源数据。

## 六、服务端与数据设计

当前 `UserPreference` 已包含：

- `appLocale`
- `learningLanguage`
- `promptDifficulty`
- `guideState`

但当前没有来源渠道字段。第一版把单个首次来源作为 `UserPreference` 的可空字段保存，不塞进 `guideState` 或 Authing：

```text
acquisitionSource
```

服务端接口需要保证：

- 来源枚举严格校验；
- 普通用户只能在字段为空时写入首次来源，重复请求返回现有值；
- 偏好与来源的同步可安全重试；
- 管理后台后续可以按渠道查看注册或活跃用户，但首期不要求制作统计页面。

第一版复用 `/me/preferences`，并在 Repository 层保证字段为空时才接受首次来源。若未来需要多触点归因、投放活动或渠道变更历史，再迁移到独立归因模型。

## 七、与现有流程的合并

实施时需要：

- 用新的全屏四步流程替换 `UiLocaleSetupModal`；
- 把 `LearningPreferenceModal` 中的学习语言与难度前移到登录前步骤；
- 登录成功后只做同步与失败重试，不再显示 `GUIDE_FIRST_LEARNING_SETUP` 弹窗；
- 保留“我 > 语言设置”，用户登录后仍可修改界面语言、学习语言和难度；
- 来源渠道不放入普通语言设置；如将来需要更正，应由独立入口或后台操作完成；
- 与账号系统改造保持解耦：无论登录最终来自 Authing 还是 OIO 自建认证，同步目标都必须是 OIO 用户 ID。

## 八、兼容和异常边界

- 用户在第 2～4 步杀掉 App：下次从未完成步骤继续，不丢前面选择；
- 用户在完成四步后、登录前杀掉 App：下次直接回到登录页；
- 登录失败或取消：保留选择，不重复四步；
- 登录成功但偏好同步超时：允许进入主界面，后台重试，不能再次弹窗；
- 同一设备切换账号：只有当前引导产生的待同步草稿可写入一次，不能把上一个账号的普通本地缓存覆盖到下一个账号；
- 已有账号在重装后完成引导：三项学习偏好按本次明确选择更新，来源渠道保留账户原值；
- 老版本升级：不得因为缺少新 Key 而强制展示；需要用现有安装证据完成一次兼容迁移。

## 九、验收范围

### 自动化

- 全新安装依次完成四步后才可进入登录页；
- 每一步未选择时不能继续；
- 切换 App 语言后当前页、后续页及登录页立即换语言；
- 中途退出后恢复到正确步骤；
- 老版本升级、已有 Session、已完成引导三种情况均不重复展示；
- 登录成功后偏好写入正确账户，来源只写首次值；
- 同步失败可重试且不会阻止进入主界面；
- 退出并登录另一个账号不会串写上一个账号的数据。

### 模拟器与真机

该改动涉及启动、登录、持久化和服务端同步，属于核心流程改动。Codex 完成自动检查后提供以下体验清单，由用户手动验证；除非用户明确要求代测，否则不主动启动模拟器、截图或执行视觉巡检：

1. iOS 当前最低支持系统；
2. iOS 最新系统；
3. Android 模拟器；
4. 国内 Android 与 Google Play 渠道配置各核对一次。

每轮只启动一套模拟器，避免并行运行造成 Mac 内存不足。必须覆盖全新安装、升级安装、退出登录、重装、网络断开后恢复五条路径。

## 十、实施拆分建议

1. 确认四步视觉稿、难度说明文案及五个来源选项；
2. 建立本地 onboarding 状态机和兼容迁移；
3. 完成全屏四步 UI，并删除两个旧弹窗触发路径；
4. 增加来源归因数据结构、API 和迁移；
5. 接入登录成功后的幂等同步与重试；
6. 补齐自动化、模拟器和真实账户验收；
7. 验收通过后再决定随新包发布，不以 OTA 先行替代完整启动链路验证。

## 十一、第一版已确定

- 难度继续沿用“初级 / 进阶”两档，并在引导页补充面向用户的解释；
- 来源固定为 YouTube、小红书、抖音、App Store、Google Play，不增加跳过或其他；
- 来源首期只落库，不建设管理后台统计页；
- App 发布从功能开发中拆开，用户完成体验验收后再单独发起 OTA 或原生发布流程。
