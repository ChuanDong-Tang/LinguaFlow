# LinguaFlow 开发与学习文档

`dev-notes` 用来保存理解、维护和继续开发 LinguaFlow（App 名称 OIO）所需的资料。这里不保存密钥、Token、证书、生产用户信息或支付数据。

## 第一次了解项目

建议按下面的顺序阅读：

1. [项目地图](./00-PROJECT-MAP.md)：仓库里有什么，功能入口在哪里。
2. [本地开发手册](./01-LOCAL-DEVELOPMENT.md)：如何启动、检查和排错。
3. [架构说明](./02-ARCHITECTURE.md)：各层职责、依赖方向和原生边界。
4. [核心业务链路](./03-BUSINESS-FLOWS.md)：重要功能的数据如何流动。
5. [学习路线](./LEARNING-ROADMAP.md)：按真实功能逐步建立维护能力。
6. [分主题学习笔记](./learning/README.md)：按 TypeScript、React Native、后端和原生专题深入。

## 其他文档区域

这些资料不属于系统学习主线，但有各自用途：

- `1.x.x/`：对应版本的阶段计划与实现记录。
- [`product/`](./product/README.md)：尚未排期的产品方向、方案假设和用户反馈。
- `style/`：OIO 设计语言和界面规范。
- `logs/`：按日期记录开发过程。
- `DECISIONS.md`：长期技术决策及原因。
- `DEVELOPMENT-ROADMAP.md`：项目治理与工程建设路线，不是个人学习课程。
- `REFACTOR-BACKLOG.md`：可选重构机会，不代表需要立即实施。
- 其他中文目录：特定阶段的产品、推广或业务计划。

## 文档职责

- 项目地图回答“代码在哪里”。
- 架构说明回答“为什么这样分层、谁可以依赖谁”。
- 业务链路回答“一次真实操作经过哪些模块”。
- 本地开发手册回答“如何运行、验证和排错”。
- 学习路线回答“下一步应该学什么”。
- `learning/` 回答“某个技术概念在本项目里怎么用”。
- 版本计划和日志记录阶段性过程，不应成为长期架构事实来源。

## 维护原则

- 先记录代码当前行为，再记录理想设计；不要把计划写成已经实现。
- 无法从代码或实际验证确认的内容标记为“待验证”。
- 功能入口、调用链或运行方式改变时，同步更新对应文档。
- 时间敏感的检查结果写明日期；过期后删除或重新验证。
- 文档示例只使用变量名和占位值，不粘贴 `.env`、账号或生产数据。
