## 1. 本文用途

1.0.7 的其他主要功能已经基本完成。本阶段只继续开发“回忆”模块。

接手者应先阅读本文，再检查当前工作区的 `apps/mobile/src/screens/RecallScreen.tsx`、Card 详情与练习页面，以及现有 Recall 前后端代码。当前 `RecallScreen` 已有 mock，不应从零重写；先体验现状，再在现有方向上迭代并接入真实数据。

工作区可能包含尚未提交的移动端改动。不得覆盖、回滚或顺手提交与回忆无关的用户代码和开发文档。

## 2. 产品定位

回忆不是搜索结果页、关系图谱、每日复习任务，也不是必须答题才能推进的学习关卡。

它是用户主动探索自己以前 Card 的“记忆地图”：以真实 Card 为节点，以真实语义关系为路线，在竖屏地图上逐步向前探索。体验参考《剑与远征》等手机竖版闯关地图，但视觉和文案保持 OIO 安静、生活化的气质，不照搬战斗、战力、星级和奖励系统。

基本映射：

| 地图概念 | OIO 中的含义                         |
| -------- | ------------------------------------ |
| 章节     | 一次回忆旅程或一个主题               |
| 普通节点 | 一张真实 Card                        |
| 路线     | Card 之间真实存在的语义关系          |
| 分岔     | 两个不同的相关方向                   |
| 特殊节点 | 成长瞬间：第一次主动用出曾挖空的短语 |
| 节点内容 | Card 回看，以及可选的填空、听写      |
| 已完成   | 本次旅程中已经打开过                 |
| 当前节点 | 下一张可打开的 Card                  |
| 未探索   | 尚未打开或尚未选择的相关 Card        |
| 章节终点 | 本次旅程的简洁路径总结               |

## 3. 已确认的产品规则

### 3.1 数据边界

- 回忆首版只使用正式 Card，不混入随手记和旧聊天记录。
- 所有节点内容、日期、图片、生活集和关联原因必须来自真实用户数据。
- 不允许 AI 补写用户没有记录过的经历、情绪和事实。
- 内部可以继续使用 Topic、Phrase、Progress、embedding 等关系，但前端不展示数据库式关系类型。
- 用户输入的“话题”是语义探索意图，应优先使用 embedding/topic 召回，不是简单的字符串关键词匹配；语义不可用时允许词法降级。

### 3.2 入口

回忆首页只有三个产品入口：

1. 今天：当天 Card 组成的线性路线。
2. 昨天：昨天 Card 组成的线性路线。
3. 探索：点击后选择“随便开始”或输入一条话题线索。

“随便看看”和“从一个话题开始”不应继续作为两个并列首页入口，它们属于“探索”的二级动作。

如果存在未结束的真实 Session，可在首页上方增加“继续上次回忆”，直接回到当前节点；没有未结束 Session 时不要占位。

### 3.3 Card 数量不足

- 完全没有 Card：三个入口不可进入，明确提供“制作第一张 Card”。
- 有少量 Card：能形成路线的入口可用，数据不足的入口置灰；提供“制作更多 Card”。
- 今天或昨天没有 Card：只禁用对应日期入口，不影响探索。
- 不为了凑满地图而重复 Card 或引入随手记。

### 3.4 路线规则

- 今天、昨天是按时间形成的线性路线，不出现人为分岔。
- 探索从一张真实 seed Card 开始，根据真实关系逐步展开。
- 普通节点最多展示两个下一方向，移动端不同时展示 3 个以上选择。
- 当前旅程中已经经过的 Card 不重复出现，用户主动回退除外。
- 单次旅程建议 5～8 个节点；首版后端硬上限可继续使用 12。
- 只有一个候选时继续单线前进；有多个候选时选择质量最高且方向差异明显的两个。
- 分岔文案应从目标 Card 的真实内容、日期或关系中提取为自然语言，不显示“Topic 相关”“Phrase 相关”等内部术语。
- 选择一条分支后，另一条可保留为未探索路线，允许回退到分岔点重新选择。

### 3.5 成长瞬间

- 成长瞬间只在用户的“我的记录/原文”中第一次主动用出以前 Card 的挖空短语时成立。
- 来源必须是另一张历史 Card 的 AI 改写/目标表达中的已挖空短语。
- 同一个短语只记录第一次主动使用。
- 一次使用多个符合条件的短语时，首版只选一个最明确的成长瞬间，不堆叠多个特殊节点。
- 地图上用克制的金色特殊节点表示；不要做金币、宝箱、奖励弹窗。

### 3.6 推进与练习

- 打开并阅读节点即可继续，不强制完成练习。
- 节点详情必须复用 Card 详情的数据和交互，不复制一套简化版业务逻辑。
- 节点内提供回看、填空、听写；行为与正式 Card 详情一致。
- 练习状态继续写回同一张 Card，不能产生 Recall 专属的第二套挖空/听写数据。
- 从节点详情返回时回到原地图位置和当前路线，不重新生成 Session。

### 3.7 结束与恢复

- 支持返回上一节点、回到分岔点改选、中途退出和恢复未完成 Session。
- 结束页只展示经过的 Card 数、起止日期和简洁路径。
- 不由 AI 总结用户人生，不输出没有数据依据的结论。
- 结束后 Session 标记完成；再次进入首页不再显示为“继续上次回忆”。

## 4. 前端交互与视觉

### 4.1 首页

当前 mock 已完成第一轮改造：

- 今天、昨天为两个并排的小入口。
- 探索为更醒目的主入口。
- 探索弹层内包含“随便开始”和话题输入。
- 保留“充足/较少/没有”的开发态切换，用于验证空状态；正式版本必须移除。

下一轮需要继续真机打磨：

- 页面保持简洁，不添加大段产品说明。
- 今天、昨天显示真实片段数或不可用状态。
- 探索入口可展示极简路线预览，但不能像营销 Banner。
- 如果加入“继续上次回忆”，它的视觉优先级高于今天/昨天。

### 4.2 章节地图

最终方向由横向路线调整为《剑与远征》式手机竖版地图：

- 地图纵向延伸，用户从屏幕下方向上推进。
- 路线轻微左右蜿蜒，不是垂直时间轴，也不是数据库关系图。
- 进入地图后自动滚动到当前节点。
- 已完成节点使用稳定实心/勾选状态；当前节点最醒目；未探索节点弱化。
- 普通路线在左右之间自然摆动；出现两个候选时才形成清楚的左右分岔。
- 路线移动和节点状态变化必须有连续动画，不能突然跳位。
- 地图可滚动查看已走过路径，但默认聚焦当前节点。
- 节点标题只显示一条短线索，可来自日期、Card 片段或主题，不塞入完整正文。
- 有图 Card 可以使用小缩略图丰富节点，但无图节点必须同样成立，不能依赖图片维持布局。
- 成长瞬间使用整节点的细金色强调，颜色和线宽统一，不使用上细下粗或夸张发光。

当前 `RecallScreen.tsx` 内仍包含横向线性地图和分叉 mock。接手者应把它改为竖向蜿蜒地图，并同时保留：线性路线、分岔路线、已完成/当前/未探索、成长瞬间四类状态的 mock 演示。

### 4.3 节点详情

- 地图点击当前可用节点后进入 Card 详情。
- 详情保持日期、图片、目标语言表达、我的记录的既有顺序。
- 复用现有 `CardDetailModal` / Card 详情导航及回看、填空、听写逻辑。
- 不用 Alert 假装练习；真实接入阶段必须打开真实详情。
- 返回地图时应保留滚动位置、当前节点和已经走过的路线。

### 4.4 动效

- 节点解锁：轻微放大和淡入即可。
- 路线推进：连接线先延伸，再出现下一节点。
- 分支选择：选中路线加强，未选路线淡化但可通过回退恢复。
- 地图定位使用平滑滚动。
- 首版不做人物立绘、GAL 对话动画、3D 场景和复杂粒子效果。

## 5. 当前技术基线

### 5.1 已有前端

- `apps/mobile/src/screens/RecallScreen.tsx`：当前回忆 mock、首页、封面、节点阅读、路线选择和结束页。
- `apps/mobile/src/services/api/cardApi.ts`：已有 seed、search、create session、active session、expand node、update node、finish session 请求。
- Card 详情、填空、听写、查词和 TTS 已在其他页面实现，应复用。

### 5.2 已有服务端

- `RecallService.seedCandidates`：推荐/随机 seed。
- `RecallService.search`：支持 embedding 语义搜索，失败时词法降级。
- `RecallService.create`：创建 Session 并展开 seed。
- `RecallService.active/get`：恢复 Session。
- `RecallService.expand`：通过真实 Card 关系展开节点。
- `RecallService.updateNode`：`unvisited/current/completed` 状态。
- `RecallService.finish`：结束 Session。
- `PrismaRecallRepository`：Session、Node、Edge、候选图片及相关持久化。
- 当前 `NODE_LIMIT = 12`。

### 5.3 接入前必须核对

- 今天/昨天是否已有直接按日期取 Card 的接口；没有则增加专用查询，不要在客户端拉全量后过滤。
- Session 返回的 Node/Edge 是否包含地图所需的日期、短标题、图片、生活集和关系摘要。
- 当前节点状态更新是否足以表达真实走过顺序、分岔选择和恢复位置。
- active Session 是否会因不同入口互相覆盖；需要明确同一用户只保留一个活动 Session，或按 launch mode 区分。
- Topic、Phrase、Progress 候选排序是否会产生两个几乎相同的分支。
- 关系展开的单向规则继续保持，避免 A→B→A 无限来回。

## 6. 建议实施顺序

1. 体验并截图当前 Recall mock，确认不要破坏已完成的 Card 页面。
2. 将节点地图改成竖向蜿蜒地图；先用 mock 完成线性、分岔、成长瞬间和空状态。
3. 冻结地图视觉、节点状态和动画，不要一边接后端一边反复改结构。
4. 梳理现有 Recall API 类型，补足日期路线和地图预览所缺字段。
5. 接入今天、昨天真实线性路线。
6. 接入探索 seed、语义话题搜索、Session 创建和节点展开。
7. 将节点点击接入真实 Card 详情与练习。
8. 实现 active Session 恢复、回退改选、结束和首页“继续上次回忆”。
9. 移除所有 `MOCK_SCENES`、Alert 占位和开发态 Mock 切换。
10. 完成 iOS/Android 真机回归和性能检查。

## 7. 验收标准

### 7.1 产品

- 首页正式状态只呈现今天、昨天、探索，以及有需要时的继续旅程。
- 无 Card、少量 Card、日期无 Card 都有正确状态和建卡入口。
- 今天/昨天严格使用对应日期的真实 Card，并按时间形成单线。
- 探索可以随机开始，也可以从话题语义召回开始。
- 地图是手机竖版、向上推进、轻微蜿蜒的章节路线，不是列表、横向轮播或关系图。
- 分支最多两个，且两个方向对用户而言有可辨认差异。
- 每个节点都能进入真实 Card；返回后保持地图现场。
- 练习完全复用 Card 详情，且不是推进的强制条件。
- 旅程可以退出、恢复、回退、改选和结束。
- 用户不会看到 Topic/Phrase/Progress、embedding、node/edge 等内部术语。
- 不出现 AI 编造的用户经历。

### 7.2 稳定性

- 当前 Session 不因杀进程、切换首页或打开 Card 详情而丢失。
- 当前旅程不重复节点，不形成 A→B→A 循环。
- 12 个节点以内地图滚动与动画流畅；节点详情不重复加载全量 Card 列表。
- 图片缺失、关系不足、embedding 失败、单候选和零候选都有降级表现。
- iOS 与 Android 的地图位置、返回逻辑和手势一致。
- Mobile TypeScript、服务端 TypeScript、Prisma 校验和相关测试通过。

## 8. 本阶段不做

- 随手记和旧聊天进入回忆。
- 强制练习、星级、经验值、连续签到和战力。
- 宝箱、金币、抽卡、排行榜和社交分享。
- AI 人生总结或虚构剧情。
- 人物立绘、GAL 对话动画、3D 地图和重粒子特效。
- 无限地图、多人路线和复杂成就系统。
- 为开发回忆而重构整个 App 导航或 Card 数据模型。
